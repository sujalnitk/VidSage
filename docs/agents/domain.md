# Domain docs

## Read before exploring

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records in `docs/adr/`.

Read the glossary and ADRs relevant to the work.

If they do not exist, proceed silently. Do not suggest creating them
upfront. The domain-modeling skill creates them when terminology
or decisions are resolved.

## Vocabulary and decisions

Use glossary terms consistently in specifications, tickets, code,
and tests. Reconsider invented synonyms; note real vocabulary gaps
for domain-modeling.

If a proposal contradicts an ADR, identify the conflict explicitly
and explain why the decision should be reopened.
